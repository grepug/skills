# iOS 开发与设备测试

帮助 agent 从缺失环境到可用通道，再完成构建、安装、测试和结果验收。代码修改遵循目标项目规范。本技能不替代 iPhone use 的操作说明。

## 通道选择

| 目标 | 默认通道 | 设置入口 |
| --- | --- | --- |
| 真实 iPhone | iPhone use 的工具；底层 WDA 由其 setup 管理 | [真机设置与使用](references/iphone-use.md) |
| iOS 模拟器 | Appium XCUITest Driver 管理 WDA，使用 Appium 客户端操作 | [模拟器设置与使用](references/simulator-wda.md) |
| 已有模拟器 WDA | 先核验目标和独占控制，再通过 Appium 接入；已有成熟直接客户端也可复用 | 同上 |

模拟器默认选 Appium 管理 WDA，是因为它提供维护中的生命周期与测试接口，避免另写一套 WDA 启动、会话及手势实现。Appium 增加一层依赖，但能复用现有测试框架，且有明确的多实例配置。这里的 WDA 指 WebDriverAgent；Appium 是管理与客户端接口层，不能把两者的端口或会话混用。

首选通道失败，先按具体缺项完成设置或修复。修复仍不可用时，说明原因和验证限制，询问是否允许降级到 computer use；真机如需 iPhone 镜像也须明确说明。没有实际答复不降级。截图、控件树和设备坐标操作仍属于原通道，不是 computer use。

## 开始时绑定目标

先说明下一步，识别项目、scheme、目标 App、用户要验证的行为和完成条件。能通过工具发现的事实自己查，不让用户抄端口或 UDID。多个同样符合条件的设备且意图不明确时，请用户选择，并推荐理由明确的目标。

在仓库外为本任务维护一份目标记录：目标类型、UDID、机型与系统、App bundle ID、构建产物与源码 revision、控制通道、endpoint、运行目录、相关端口、会话 ID、绑定证据、任务拥有的 job/进程及日志路径。使用当前证据更新，不能沿用另一个设备的会话或坐标。

**可达、绑定正确、归属当前任务是三个不同事实。** `/status`、`READY`、手机预览标题或配置中的 UDID 都不能单独证明端口实际对应哪台设备。多个实例、外部服务或配置与监听不一致时，先读 [多 WDA 实例排障](references/multiple-wda.md)，把 UDID、启动/转发进程、endpoint 和会话关联起来，再操作目标 App。无法建立关联时保持未验证，不用点击来猜设备。

基础模式为多个实例共存、一个任务控制一个目标；设备矩阵依次执行。不同目录和端口不能解决同一 UDID 被两个 agent 同时控制的问题。已有任务持锁或控制该目标时先协调释放，不能换目录绕开。

## 构建、安装与测试

1. 首次使用 XcodeBuildMCP 前读取当前安装的 `xcodebuildmcp` 技能。使用 **xcodebuildmcp CLI**，先检查 `--help` 和 `tools`，以实际版本的参数为准；技能列出的 MCP 名称不一定是 CLI 子命令。显式指定项目或 workspace、scheme、目标 ID 和任务自己的构建目录，避免修改另一个任务的共享 defaults。
2. 缺少 CLI 时，按其官方安装说明补齐并验证；不要改用 XcodeBuildMCP 的 MCP 服务或直接运行 `xcodebuild`。此约束针对 agent 发出的命令；iPhone use、Appium 和 XcodeBuildMCP 内部执行 `xcodebuild` 合法。
3. 编译检查用对应 `build`；需要构建并运行用对应 `build-and-run`，避免重复构建。已有指定产物只需安装与启动时使用对应 install/launch。CLI 当前常见入口为 `simulator`、`device`，通过各自 `--help` 确认 `--simulator-id` 或 `--device-id`。
4. 执行项目要求的单元、集成或 XCTest 测试。XCTest 与 WDA 都会使用测试服务；不要对同一 UDID 同时运行 XCTest 和交互控制。测试结束后重验控制通道，再开始交互验收。
5. 用已选通道进入目标 App，执行用户要求的路径。优先 accessibility 标识和语义定位；定位异常先看当前截图，按设备坐标处理，不能改点 Mac 上的模拟器窗口或镜像。
6. 关键最终状态必须实际核对：启动后显示正确 App/页面、输入后的实际内容、提交后的结果或记录。构建通过、进程存在、HTTP 成功、动作完成和截图文件存在都不等于功能通过。

长 JSON、文本和测试代码先保存到 `/tmp` 文件，再由 CLI 的文件参数、`curl --data-binary @文件` 或脚本读取。不要把长文本直接拼入 shell 参数。示例命令按所在项目规范加包装；要求 RTK 的环境使用 `rtk proxy`，Python 使用 `python3`。

## 设置和恢复的权限

设置通道本身属于本技能的工作：复用兼容安装，补缺失依赖，创建任务专用运行目录和日志，启动自己的服务。不为这些已授权的可逆步骤添加统一确认关卡。先检查依赖的实际版本及官方兼容要求，不为追新自动升级共享工具链。

自动恢复限于**本任务拥有且能再次核验归属**的会话、job 或进程。沿用别人启动的健康服务不意味着可以重启它；插件标记 owned 也不等于当前任务拥有。不要按端口杀进程、全局 kill、清空所有会话、删除已有运行目录或擦除设备。需要改动共享安装或中断其他任务时先给出具体影响并等用户确认。

首次安装可能需要用户完成 Xcode 登录、手机信任、开发者模式或解锁。说明准确步骤，等待真实完成通知，不索取密码或验证码。App 认证沿用 iPhone use 的暂停预览与用户接管流程；它不是 WDA 故障。网络中断或动作超时后，先观察真实状态再决定是否补做，不能重放可能已经生效的输入、提交或整个批次。

## 交付与清理

逐目标报告源码/产物、UDID、通道、绑定证据、已执行测试、结果证据与限制。设置完成分别说明依赖可用、目标绑定正确、通道可操作；应用验收另行报告。局部验证只能称为局部验证，不能据此声称真机、完整设备矩阵或 CI 已通过。

保存当前任务的日志、截图、失败现场和复现步骤；敏感设备及签名配置留在仓库外。结束自己的 Appium 会话，按原计划保留或停止自己启动的服务；保留复用的外部服务。设备矩阵切换时重新绑定下一个目标并验收通道，不复用前一个目标的 element ID、session ID 或观察坐标。
