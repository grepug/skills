# Keep state-driven verification local and scenarios disposable by default

State-driven development needs real, current evidence without accumulating brittle workflow scripts that quickly encode obsolete product details. Keep the reusable harness and runner in the adopting repository, but generate feature-specific scenarios under a Git-ignored scratch test target, run them locally against the current authoritative system, record commit-bound evidence, and delete them. Skill-produced tests may compile in CI but must never execute there; retain a local regression only when a stable harmful recurrence cannot be protected at a smaller faithful seam. This trades automatic historical coverage for lower maintenance cost and forces each delivery claim to be regenerated from the current product contract.
