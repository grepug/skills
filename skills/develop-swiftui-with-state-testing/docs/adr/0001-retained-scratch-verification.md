# Keep state-driven verification local, uncommitted, and retained by default

State-driven development needs current evidence without forcing every acceptance scenario into the maintained test suite. Keep the reusable harness and runner committed, but generate feature-specific scenarios under a Git-ignored Scratch test target, run them locally, record commit-bound evidence, and retain the source in the worktree for debugging and reuse. Never track or stage Scratch source, and never delete it automatically; the user owns deletion, commonly through worktree cleanup, unless they explicitly authorize an agent to remove it. Continue to clean runtime processes, credentials, run-owned product data, client files, and sandboxes automatically. Revalidate retained scenarios against the current acceptance claim before reuse, and promote one only with explicit user approval by migrating it into the maintained test suite.
